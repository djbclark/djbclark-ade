## 2. Facts needed to read the numbers

1. **Gradle 8.13** (wrapper), **AGP 8.11.0**, **Kotlin 2.0.21**; local **JDK 21.0.12.1 (Homebrew openjdk@21)** via `bg env JAVA_HOME=/opt/homebrew/opt/openjdk@21`. CI uses Temurin **JDK 17** on ubuntu-latest. Only the **StableDebug** variant was ever built locally: no `testStableRelease`, `testNightly*`, `testPlay*`, `lintStableRelease` or `lintNightly*` run exists anywhere.
2. **Local daemon is throttled**: `-XX:ActiveProcessorCount=2 -Xmx2g` (daemonOpts in every daemon log), Kotlin daemon `-Xmx4096m` (gradle.properties); `org.gradle.parallel` is commented out; VFS watching off. The Mac has 8 cores and `bg` reports load 12-175 while waiting. A GitHub runner has 4 vCPU and a fresh checkout.
3. **Gradle-printed time includes the machine-wide Gradle slot wait** (init script `machine-slot.gradle` blocks inside Gradle while another build holds the lock; log line `machine-gradle-slot: got the Gradle slot after N s`, or `Waiting for the machine-wide Gradle slot` printed every 60 s). It does **not** include the `bg` pre-start wait (`bg: load N on 8 cores is above 1.5 per core; waiting`, capped at 900 s, and `bg: waiting for a machine-wide Gradle slot`, capped at 1800 s), which happens before Gradle starts. Columns: "Slot wait inside" (a `~` prefix means estimated from 60-second notes, no exact line) and "Net of slot" = Gradle time minus that wait. For rows with transcript command timestamps the pre-start wait is in the notes.
4. **Build cache**: local disk build cache is on, and since 2026-10-13 a remote Develocity cache node (`global-remote-cache.init.gradle.kts`) may be attached. Rows with `(N cache)` in the Tasks column pulled tasks from cache (they appear first in the 2026-10-13 ~16:20 UTC builds), so they understate compile time.
5. **Cold vs warm** = daemon log: `Starting build in new daemon` = **cold** (first build in a fresh daemon JVM); no such line = **warm** (reused daemon; Gradle prints nothing for reuse at default log level, so no log file has `Reusing a Gradle Daemon`). "Tasks (exec/total)" is the `N actionable tasks: X executed` line; 28/28 means a fresh worktree/build dir (nothing up to date).
6. Per-test-class failures: every full-suite FAILED row failed only on tests (mostly the known upstream `CornerButtonThemeTest.outerButtonFollowsInnerLedThroughTheBottomOfTheSlot`, 1-2 others in a few rows), after compilation, so those durations are valid. Rows marked `X` stopped early (compile error, resource error, invalid task name, Gradle install damage, AGP build-dir error) and are **not comparable**.
7. **Class legend** (last-but-one column): `A` full `:app:testStableDebugUnitTest` (alone or with assemble; matches CI step "Run stable debug unit tests"); `B` filtered `--tests` runs (compile + a few classes); `C` `:app:lintStableDebug` (CI step "Run stable debug lint"); `D` assemble/compile only (not in CI); `B+C` mixed; `X` not comparable; `?` after a letter = inferred from the test count/log, command not recorded. `A*` = valid but dominated by slot wait, use the net column.
8. Times in the table: End (UTC) as `MM-DD HH:MM`; EDT = UTC minus 4 h (same clock time shown, the date can be the previous day for 00:00-03:59 UTC). Daemon start = end minus Gradle time.
