## Failed observational CLI calls

remain available when a timeout or disposal failure prevents a normal response.

status only. CLI stdout and owner-bearing call diagnostics remain excluded;
original deadlines, caps, error ordering and settlement refusal stay unchanged.

These source changes do not qualify a snapshot or prove natural cleanup. The
failed actual probe is retained as evidence; a changed source unit needs source

## Waiting for normal publication before calling the CLI

The disposable probe waits for its original daemon handle's normal
home/paseo.pid record to publish the original fixture socket and a server ID.
This only schedules the existing CLI invocation. It does not supply the CLI
with an endpoint, grant execution, or stand in for a readiness/owner proof.
The public CLI still verifies the distribution and discovers/connects itself.

Waiting consumes the same 180-second startup deadline and 500 ms cadence.
Each actual CLI keeps its 15-second transport budget. Initial absence, empty
in-place writes and changing reads remain pending. Stable malformed data,
unexpected identities/endpoints, replacement, withdrawal after readiness,
I/O failures and loss of the original child remain failures. Actual CLI
registration/status/BEGIN refusal, private observation and natural teardown
checks still decide the probe result. Synthetic metadata and FD tests are
scheduling DATA tests; they confer no native or cleanup qualification.
