# Skills: what each one is and how to use it

Regenerated by hand 2026-11-07 (slim-down E11) against the skills in [`skills/`](../skills/); README's roster is the
generated one-line list (`bin/ade-roster`). Each directory holds a `SKILL.md` (the instructions an agent loads) plus
any scripts or reference files beside it. Every **current** local TUI (Claude Code, Codex, Pi, Cursor, Hermes; Pi is the
sole third-party TUI since 2026-11-09) links the skill **directly** at this repo, one symlink, no chain, so an edit here
reaches every agent. omp and OpenCode are retired targets (history only; see [tui-lessons-learned.md](tui-lessons-learned.md)):

```
~/.claude/skills/<name>  ->  ~/src/djbclark-ade/skills/<name>    (the real files)
~/.agents/skills/<name>  ->  ~/src/djbclark-ade/skills/<name>    (Codex and Pi share this dir)
```

`bin/skill-everywhere` makes those links from three roots: this repo, `~/ops/site-private/skills` (private skills,
such as `1password`) and `~/ops/site-public-djbclark/skills` (site skills); `docs/skill-everywhere.md` says how each
TUI finds them. After a new link, run `/reload-skills` in running Claude sessions.

**How to use a skill.** In Claude Code type `/<name>` (with arguments after it), or say one of the trigger phrases
below and the agent loads it; Codex invokes a skill with `$` (`$baton`). **A new skill always goes here** (operator
standing rule, 2026-10-09), and a skill is **edited here, never through a TUI path**. `/resume` is the one thin
Claude command wrapper left in [`claude/commands/`](../claude/commands/); every other skill's `name:` is its own
slash command.

For the migration choices, compatibility names and Linux/macOS handoffs, read
[old way versus new way](old-way-new-way.md).

## Sessions and handoffs

| `btww` | Says which native side-question command this TUI has (Claude Code `/btw`, Codex `/side`, …). | `/btww`, "btw". |

## Orchestration and routing

| Skill | What it does | How to use |
|---|---|---|
| `fan-out` | Fans separable work out and collects it: the Agent tool or a Workflow in process, or native `paseo run --no-wait` for a slice in its own worktree, then `paseo wait` / `paseo send` to collect and steer (2026-11-09; Wave 6; the transitional `acp-dispatch` shim leaves ~2026-11-20). | "fan this out", "split this across agents". |
| `model-routing` | The Claude tier for a role, effort, which pool takes a slice (`route_agent.py plan`), reading quota (aiuse, `paseo usage ls`), the frontier allowance, fallback chains (effort-routing and fallback-chains folded in, 2026-11-07). | Before a multi-agent run or when a quota window is tight. |
| `watch` | Low-token terminal load inspection, memory churn check, and incident triage (`/watch load`, `/watch`, `/loadwatch`). | `/watch load`, "check load", "triage load spikes". |
| `dialogue` | A multi-model dialogue that produces one artifact with a final-word model: fixed rounds through pinned routes (a `paseo` route runs `paseo run --no-wait`, then `paseo wait`, and reads the reply file), footers with point ids and dissent. | "have the models chat about it and write X". Script: `skills/dialogue/scripts/dialogue.py`. |
| `research` | Evidence-grounded research: every claim logged with a verbatim quote, a counter-evidence pass, a script that checks quotes and citations. | "deep research on X". Script: `skills/research/scripts/research_check.py`. |

## Adding or moving a skill

1. Put the directory in `skills/<name>/` here with a `SKILL.md` (front matter `name` and `description`).
2. Link it into every TUI: `~/src/djbclark-ade/bin/skill-everywhere <name>`, then `--check <name>`.
3. Add a row above, run `bin/ade-roster --write` for README's roster, and add a changelog fragment. Nothing private
   goes in a skill here.
