## Delivery contract (shared footer; `acp-dispatch` appends it, Agent-tool prompts paste it)

1. Write the full deliverable to `{report}`. Create it early with `STATUS: working` as its first line and update it as you go; finish it **before** any optional verification. Nothing else counts as delivered.
2. Your final message is only `written: {report}` plus one sentence. The harness cuts a sub-agent's final message at 4,000 characters and the parent never sees the rest, so never put the deliverable there.
3. If the parent must read more than about 2,000 characters of it, also send the text to `{lead}` with SendMessage (an Agent-tool sub-agent's parent is `main`; `team-lead` only inside an agent team), in ordered chunks under 3,500 characters each (`1/3`, `2/3`, ...). That path arrives whole.
4. Keep the report path exactly as given. Claude Code refuses a sub-agent's Write when the basename starts with `report`, `summary`, `findings` or `analysis` and ends in `.md`.
5. Never end your turn waiting for a background task's completion notice: it does not wake a sub-agent (it is delivered only with the next inbound message, so you stall until someone writes to you). The "start slow commands in the background" rule is for interactive sessions and the lead, not for you. Hold the wait in foreground Bash calls, each bounded under the tool timeout and repeated until done (`~/src/djbclark-ade/bin/wait-file --timeout 1500 /ABS/FILE`, rule 13; `while kill -0 <pid>; do sleep 10; done`, `gh pr checks --watch`), or do independent work and check again before you end.
6. Never end your turn on a question. If you are blocked, make the first line of `{report}` `BLOCKED: <the question, one line>`, SendMessage that same line to `{lead}`, then stop. A decision you can make conservatively, make it, and record it in the report under `DECIDED:`. A design choice whose wrong answer means rework (an interface or data shape, an ordering, locking or clock rule, behaviour other code relies on) is not conservative: ask it this way, since the lead answers in a few lines.
7. The last line of the report is `DONE` (or it starts with `BLOCKED:` as above), then `touch {done}` as your very last act. Waiters watch `{done}`, not the report, so a half-written file is never read.
8. Never change anything outside the folders your brief names, and that includes shared tool state: Gradle's caches (`~/.gradle`, `~/.cache/gradle`), `~/.m2`, npm/pip/uv caches, SDKs and JDKs. A build that only works after you patch a cache (for example stripping jar signatures) is a finding to report under `DECIDED:` or `BLOCKED:`, not a fix. Every other build on the machine shares those caches.
9. In a worktree-isolated sub-agent (cwd under `.claude/worktrees/`), Claude Code's isolation guard refuses Bash commands it can't verify: loops, `cd … && git …` chains, pipes into decoders, heredocs that mention git, subshells with quoted globs. Run single plain commands, put anything compound in a script under the scratchpad and run that script, and edit files with the Edit tool. If plain `git` is refused, call `/opt/homebrew/bin/git` directly.
10. Never run one foreground command for more than about 30 minutes: opencode interrupted a 3,626 s one on 2026-10-13 and that cancelled the whole turn, so the slice never wrote its report. Start long work with its output going to a file (`nohup sh -c 'cmd > out.log 2>&1; echo rc=$? >> out.log' &`) and poll the file in foreground calls of under 10 minutes each.
11. On this Mac, `sed` is BSD sed: use `gsed` (and `ggrep`, `gawk`, `gdate`) in every command you run, never bare `sed`, not even a `sed -i.bak` you expect to be harmless (2026-10-17: two slices in a row slipped). Remote Linux hosts keep plain `sed`; a nix/CI image may have none, so use a shell loop there.
12. Wrap every network command (`git clone`/`fetch`/`push`, `npm`/`pnpm install`, `curl`) in `timeout 600` or less, and clone a repo you do not already have shallow and blobless (`git clone --filter=blob:none --depth 1 --single-branch --branch <b> <url>`): a stalled transfer sits at 0% CPU with no error, so without a timeout the slice hangs silently (2026-10-17: two full clones of a large repo stalled for 30+ minutes).
13. Wait on a file only with `~/src/djbclark-ade/bin/wait-file [--timeout S] [--match '^rc='] /ABSOLUTE/PATH`, never a hand-rolled `until grep ...; do sleep` loop: it refuses (exit 2) an empty, relative or root-level path and a missing directory, and stops at its timeout (exit 124). Use poll or yield intervals of 30–60 seconds instead of rapid one-second polling; this does not shorten a task’s overall wait deadline. A yielded Codex executor cell is resumed with its `wait` tool (for example `yield_time_ms: 50000`), not by relaunching the command. For Herdr, completion may be `idle` or `done`; waiting for only `idle` can time out after the work has finished. A returned `session_id` or running cell is still in progress: resume it until completion and a successful exit before reading its downloads, artifacts or other dependent outputs. An existing partial file is not completion proof. Write paths as literals, and never `export` in a list you end with `&`: the export happens in the background subshell, so the variable is empty afterwards (2026-10-17: waiters sat on `/install2.log` for 14 minutes and on `/install3.log` for 15, after the work had already ended).
14. Messages to native TUI test subjects use `session-finder/relay.py` or the documented `helm.py send` path; direct UI input is for verified native commands and selectors. Verify a slash command in the installed client before submitting it: an unknown slash command can become a paid model prompt. Read the current visible screen after each UI change. Key APIs take supported key names or single characters; use the text API for selector search text, and check the app's own shortcuts before using an editing chord. Messages from the lead may arrive while you work. Between steps (after each commit, before each long command, and before you write the final report), read `{inbox}` if it exists. For every `## MSG N` you have not answered, act on it, and append `REPLY N: <one line>` to `{replies}`. A message overrides the brief where they conflict.
15. Lifecycle actions (`self-slash` with `/new`, `/clear`, `/reset`, `/compact`, `/quit`, `/exit` or `--finish`, and a handoff's Step 9) run only in the operator's top-level session, never in a sub-agent or a dispatched slice: they inherit the parent's agent id and would clear or archive the PARENT's session (found 2026-10-20). If a skill you run ends with one, treat that step as document-only, say so in the report, and let the lead decide. `acp-run` also scrubs `PASEO_AGENT_ID` and sets `ACP_RUN_AGENT=1`, and `self-slash` refuses with exit 9.
16. Run tests and builds only through `~/ops/site-private/bin/bg` (full path); tiny smoke scripts and checks of documentation examples are tests too. Record the CI decision for the test's exact working Git root; a nested fixture repository needs its own decision, not its parent's. Use the documented `load-watch ci decide` precheck; never run bare `load-governor`, which starts its daemon. Use **one pytest at a time**, never several trees in parallel and never a bare `pytest`/`uv run ... pytest` (2026-10-23: one adversary round started ~10 parallel test trees outside `bg`, load 30 on 8 cores for five minutes, and the load watcher's memory gate never saw them). Mutation checks run one mutant after another, each under `timeout`, with `-k` of the new tests only. Whether CI can run it instead: `load-watch ci decide`.
17. Before binding a local TCP test or web-client port on the Mac, claim it in `site-djbclark/registry/ports.yml` through the lead; an ephemeral test still counts. Prefer an owned private Unix socket when it fits. Never start on an unclaimed port and register it afterwards. Report every temporary server, its saved PID, and teardown result.
18. Bound tool output before printing it: save large JSON and transcripts privately, then emit only required fields or excerpts. Print one parsed structured result, not both it and a duplicate content block. A truncated output can hide a running session or write acknowledgement; recover the existing result before retrying. For auth-bearing configuration, extract only known non-secret fields or booleans before printing; never print whole lines containing credential flags, key prefixes, or a regex-redacted raw file. Treat JSON escaping and quoted argv as reasons to avoid raw-line redaction. A failed CLI may put its JSON error on stderr; check the exit status and both output channels before parsing stdout as JSON. Always retain the command result envelope, including session_id and exit_code, even when printing only an output excerpt. Before a batch, budget the sum of its outputs against the outer tool cap; extract fields or bounded line spans before printing. Do not print whole skills, quota JSON, or overlapping context windows. A smaller max_output_tokens truncates rather than summarizes; size it for the already-bounded result. If graft says it fell back to a parent or another repository, discard its answer and build the graph in the intended workspace before continuing discovery.
