# Scheduling: one plist, three schedulers (`bin/ade-sched`, 2026-11-04)

The repo's unattended jobs (sweeps, watchers, collectors) are written as launchd plists in [`launchd/`](../launchd/) and
[`config/launchd/`](../config/launchd/). Those plists stay the **source of truth**. [`bin/ade_sched.py`](../bin/ade_sched.py)
(a library, issue #279 slice S0) and its CLI [`bin/ade-sched`](../bin/ade-sched) read a plist, fill its placeholders and
install it on whatever this machine schedules with: (Python 3.10 or later for `ade-sched` itself; `pr-policy` needs 3.11+ for `tomllib` (`context-budget-check`, which also does, runs as a Paseo schedule since 2026-11-06, not through ade-sched), so on Ubuntu 22.04, whose python3 is 3.10, install a newer Python first; 2026-11-04):

| backend | what it writes | how it activates |
| --- | --- | --- |
| `launchd` (macOS) | the filled plist, `~/Library/LaunchAgents/LABEL.plist` | `launchctl bootout gui/UID/LABEL` (result ignored), `launchctl bootstrap gui/UID PATH` |
| `systemd` (Linux) | `LABEL.service`, plus `LABEL.timer` for a timed job, in `${XDG_CONFIG_HOME:-~/.config}/systemd/user` | `systemctl --user daemon-reload`, `enable` the timer (or service), `restart` it (a service: `restart --no-block`) |
| `cron` (fallback) | a `# BEGIN ade-sched:LABEL` .. `# END ade-sched:LABEL` block in the user's crontab | `crontab -l`, drop the old block, append the new one, `crontab -` (under a `flock` on `${XDG_STATE_HOME:-~/.local/state}/ade/ade-sched.lock`) ; each run is `mkdir -p ~/.local/state/ade && flock -n ~/.local/state/ade/LABEL.cron.lock ...` when `flock` is on PATH, so a run that outlasts its interval is not started twice (2026-11-05) |

Every generated unit and cron block starts `# generated by bin/ade-sched from <plist>; edit the plist` (the launchd copy
carries the same text as an XML comment). Edit the plist, then install again; never edit the generated file.

**Which jobs belong here (Paseo directive F2, [paseo-only-rearchitecture.md](paseo-only-rearchitecture.md)).** System jobs
(monitors, collectors, record reaping, watchdogs, sweeps) use launchd on the Mac and systemd on Linux, through this tool.
Judgment jobs that run an agent (triage, reports) use Paseo schedules (`paseo schedule create --cron ...`),
not ade-sched. **Every `paseo schedule create` passes an explicit `--mode`**: `auto` for Claude, `auto-review` for
Codex. A schedule run is created unattended, and with no `--mode` Paseo gives it the provider's unattended mode
(Claude `bypassPermissions`, Codex `full-access`), so a job that reads outside text would run with no guard. This
comes from Paseo 0.15.3's source, `packages/server/src/server/schedule/service.ts` and `create-agent-mode.ts`, read on
2026-11-07.

## Commands

```
bin/ade-sched [options] backend               the backend auto-detection picks, its unit/agent dir, the linger state
bin/ade-sched [options] render PLIST          print what install would write (one `# <path>` header per artifact)
bin/ade-sched [options] install PLIST         write and activate the job
bin/ade-sched [options] uninstall LABEL       remove it (not installed: exit 0)
bin/ade-sched [options] status [LABEL...]     installed / active / next run; no LABEL: every job ade-sched generated

Checked-in ADE jobs under `config/launchd/` include `com.djbclark.deadline-sweep`,
`com.djbclark.pr-policy`, and (2026-11-09) `com.djbclark.ade-update-check` (daily
`ade-update --check` only; not installed until an operator runs `ade-sched install`).
```

| option | meaning |
| --- | --- |
| `--backend auto\|launchd\|systemd\|cron` | default `auto` (the detection below) |
| `--ade DIR` | the checkout that fills `__ADE__` / `@ADE@`; default: the checkout `bin/ade-sched` is in |
| `--set KEY=VALUE` | fill a placeholder, written exactly as in the plist (`__STATE__=...`, `@TARGET@=...`); repeatable |
| `--dry-run` | install/uninstall: print every artifact and command, change nothing |
| `--no-activate` | install/uninstall: write or remove the files and print the activation commands instead of running them |
| `--allow-no-linger` | systemd install: proceed although `Linger=no` (see Linger) |

The options go before or after the subcommand.

### Linux quickstart

```
bin/ade-sched backend                     # expect: backend: systemd (systemd user manager running), linger: yes
bin/ade-sched render config/launchd/com.djbclark.deadline-sweep.plist --set __STATE__=$HOME/.local/state/deadlines
bin/ade-sched install config/launchd/com.djbclark.deadline-sweep.plist --set __STATE__=$HOME/.local/state/deadlines \
    --ade ~/src/djbclark-ade
bin/ade-sched status com.djbclark.deadline-sweep
systemctl --user list-timers               # the timer, its next run
```

Install from the canonical checkout (`--ade ~/src/djbclark-ade`): a job installed from a linked worktree would point into a
directory that is deleted after the merge, so install refuses that default (below).

## Placeholders

Placeholders are filled into the **parsed** plist (strings inside values, never the XML text, so a value with `<` or `&`
stays a value). `__ADE__`/`@ADE@` (the checkout, realpath) and `__HOME__`/`@HOME@` are always filled; everything else
comes from `--set` (or `subst=` in the API) and wins over the defaults. Each string is filled in one pass, so a filled
value is never filled again. Any `__NAME__` or `@NAME@` left afterwards is **exit 2**. The plists in use on 2026-11-04 need:
`config/launchd/com.djbclark.deadline-sweep.plist` and `com.djbclark.pr-policy.plist`: `__STATE__` (the `@TARGET@`/`@STATE@` and
`__REPO__`/`__INDEX_DIR__` plists, proc-cpu-watch and session-history-update, were deleted in the 2026-11-06 slim-down). Several plists still hard-code
`/Users/djbclark`; they parse and render as they are (later #279 slices template them).

XML comments are stripped before parsing: no plist here now (acp-dispatch-reap's, rumination-watch's and zcode-key-auth's had one; all three were deleted 2026-11-06)
would have `--` inside a comment, which XML forbids and Python's parser rejects while launchd accepts it.

**ade-sched's own plist key.** `KillMode` (`control-group`, `mixed`, `process`, `none`) sets systemd's KillMode; launchd
has no such key, and ade-sched leaves it out of the launchd copy. The API takes `kill_mode=` too.

## Detection (`--backend auto`)

1. an explicit `--backend` (or `backend=` in the API);
2. `ADE_SCHED_BACKEND` = `launchd` | `systemd` | `cron` | `none` (`none` turns scheduling off: exit 69); `auto` or empty is unset;
3. macOS (`darwin`) with `launchctl` -> launchd;
4. `/run/systemd/system` exists and `systemctl --user is-system-running` prints `running`, `degraded`, `starting` or
   `initializing` on **stdout** (the exit code is not read: `degraded` exits 1 and the manager works) -> systemd. When
   `XDG_RUNTIME_DIR` is unset (cron, ssh without pam_systemd, `sudo -u`) and `/run/user/UID/bus` exists, ade-sched sets
   `XDG_RUNTIME_DIR` and `DBUS_SESSION_BUS_ADDRESS` for its `systemctl` children first;
5. systemd is booted but the user manager does not answer -> **exit 69** with the export hint, never a silent fall back to cron;
6. no systemd and `crontab` on PATH -> cron;
7. otherwise exit 69 ("no scheduler").

## Overrides

| env | default | per-call keyword (API) |
| --- | --- | --- |
| `ADE_SCHED_LAUNCHCTL`, `ADE_SCHED_SYSTEMCTL`, `ADE_SCHED_LOGINCTL`, `ADE_SCHED_CRONTAB` | the binary on PATH | `launchctl=`, `systemctl=`, `loginctl=`, `crontab=` |
| `ADE_SCHED_LAUNCH_AGENTS` | `~/Library/LaunchAgents` | `agents_dir=` |
| `ADE_SCHED_UNIT_DIR` | `${XDG_CONFIG_HOME:-~/.config}/systemd/user` (a relative `XDG_*` counts as unset) | `unit_dir=` |
| `ADE_SCHED_LOCK` | `${XDG_STATE_HOME:-~/.local/state}/ade/ade-sched.lock` | `lock_path=` |

A keyword beats the env variable, so an installer could honour its own older override by passing it through; none does
since 2026-11-06 (the installers with older overrides, acp-dispatch's reap, context-budget-check's and skillopt-night's,
were deleted in slim-down E5, E6 and E10; `bin/deadline` and `bin/pr-policy` pass none). `tests/conftest.py` pins all seven variables (four binaries, two directories, the lock) to `/usr/bin/true` and a throwaway
directory, unconditionally, so no test touches a real launchd, systemd or crontab.

## Linger

A systemd user manager without linger starts at login and stops at the last logout, taking its timers with it: a job
would run only while someone is logged in (the "deadlines never enforced" failure in #279). Before writing anything, a
systemd install reads `loginctl show-user USER -p Linger --value`; `no` is **exit 69** with
`sudo loginctl enable-linger USER` in the message, unless `--allow-no-linger` (`allow_no_linger=True`), which installs and
prints the same warning. ade-sched never runs sudo. An unreadable value is a note, not a refusal. `ade-sched backend`
prints the state.

## Mapping

| launchd key | systemd | cron |
| --- | --- | --- |
| `ProgramArguments` / `Program` (argv[0] absolute) | `ExecStart=`, each argument double-quoted: `\`->`\\`, `"`->`\"`, `%`->`%%`, `$`->`$$` | `shlex.quote` each argument, then every `%` -> `\%` |
| `StartInterval N` | oneshot service + timer: `OnActiveSec=` (1 s with RunAtLoad, else N s), `OnUnitActiveSec=Ns`, `AccuracySec=1s` | N >= 60: the nearest evenly dividing step, rounded down with a note (`*/m` minutes, `0 */h` hours, daily); N < 60: **exit 69** ("cron cannot run every Ns; use systemd") |
| `StartCalendarInterval` (dict or list) | one `OnCalendar=` per dict, two when it has both `Day` and `Weekday` (either one matches, as in launchd and cron; 2026-11-06) (Weekday 0 and 7 = Sun; a missing field is `*`), `Persistent=true`, `AccuracySec=1s`; plus `OnActiveSec=1s` with RunAtLoad | one line per dict, fields as given (Weekday 7 -> 0) |
| `RunAtLoad` only | oneshot service, `WantedBy=default.target` | `@reboot` |
| `KeepAlive` (true, or `{SuccessfulExit: false}`) | `Type=simple`, `Restart=always` (`on-failure` for SuccessfulExit false), `RestartSec=10s`, `WantedBy=default.target` | **exit 69**: cron cannot supervise |
| `EnvironmentVariables` | `Environment="K=V"` (`%` escaped) | `/usr/bin/env K=V ...` |
| `PATH` in it (Mac paths) | `%h/.local/bin:/usr/local/bin:/usr/bin:/bin` first, then the plist's; set when absent | `$HOME/.local/bin:/usr/local/bin:/usr/bin:/bin` (filled at install) first |
| `WorkingDirectory` | `WorkingDirectory=` | `cd DIR &&` |
| `StandardOutPath` / `StandardErrorPath` | `StandardOutput=append:P` / `StandardError=append:P` (systemd 240+; 236-239 `file:`, which truncates; older: the journal, with a note); the parent dir is created | `>>P 2>&1`, or separate redirects; a missing one goes to `/dev/null` |
| `Nice`, `LowPriorityIO`, `ProcessType=Background` | `Nice=` (Background without Nice: 10), `IOSchedulingClass=idle` | ignored, with a note |
| (oneshot defaults) | `KillMode=process` (launchd leaves setsid-detached workers alive: bin/deadline's sweep starts them), `TimeoutStartSec=max(3 x StartInterval, 300 s)`; a calendar job: max(its shortest gap, capped at a day, 300 s) | — |
| any other key | kept in the launchd copy; a note on systemd and cron | |

Refused with exit 2 on every backend: a newline, CR or NUL in any argument, environment value, working directory or log
path; an `EnvironmentVariables` name matching `(?i)(KEY|TOKEN|SECRET|PASSWORD)` (a secret never goes into a unit file or
crontab; fetch it at run time with `sudo-secretspec get`); a relative program; a job with nothing to schedule (systemd, cron).

Files are written atomically (a temp file beside, then `os.replace`) with mode 0600. The crontab is never rewritten from a
bad read: `crontab -l` exit 1 with "no crontab" on stderr means empty; any other failure is exit 1 and nothing is written.
Foreign crontab lines and other labels' blocks are kept; installing twice leaves one block. A systemd install removes a
cron block of the same label; a systemd job that loses its schedule has its old timer disabled and removed.

**Worktree guard.** When `__ADE__` defaulted to the checkout ade_sched.py lives in and that checkout is a linked git
worktree (its `.git` file names a gitdir with a `commondir`), install refuses with exit 2 unless `--ade` / `ade=` is given;
dry-run and render are allowed.

## Exit codes

| code | meaning |
| --- | --- |
| 0 | done (uninstall of something not installed included) |
| 1 | an activation command failed (its stderr is quoted), or `crontab -l` failed for a reason other than "no crontab" |
| 2 | bad job or usage: unparsable plist, unfilled placeholder, newline in a value, secret-looking env name, worktree guard |
| 3 | `status LABEL`: a named label is not installed |
| 69 | no usable scheduler: `none` forced, nothing found, systemd user manager unreachable, Linger=no without `--allow-no-linger`, KeepAlive or StartInterval < 60 s on cron |

## API (for installers)

Callers run under `python3 -I`, so they put the script's directory on `sys.path` first, as `bin/acp-dispatch` does for `route_agent.py`:

```python
sys.path[:0] = [d for d in (os.path.dirname(os.path.realpath(__file__)),) if d not in sys.path]
import ade_sched

job = ade_sched.Job.from_plist(PLIST, {"__STATE__": str(state)}, ade=ADE)
try:
    ade_sched.install(job, launchctl=os.environ.get("X_LAUNCHCTL"), agents_dir=os.environ.get("X_LAUNCH_AGENTS"))
except ade_sched.SchedError as e:
    print(f"x: {e}", file=sys.stderr)
    return e.code
```

`Job.from_plist(path, subst=None, *, ade=None, kill_mode=None)`, `Job.from_dict(d, source, subst, *, ade, kill_mode)`,
`detect(backend=None, env=None, platform=None, which=..., run=..., booted_dir=..., run_user_dir=..., uid=None, exists=...)`
(every dependency injectable), `render(job, backend, env=None, **overrides)`,
`install(job, backend=None, *, dry_run, activate, allow_no_linger, env, out, err, **overrides)`,
`uninstall(label, backend=None, *, dry_run, activate, env, out, err, **overrides) -> bool`,
`status(label, backend=None, *, env, **overrides) -> Status(backend, label, installed, active, next_run, paths)`,
`installed_labels(...)`, `linger(...)`, `systemd_version(...)`. The module docstring is the reference.

Tests: `tests/test_ade_sched.py` (every checked-in plist on all three backends, quoting with a hostile path, the calendar
and cron mappings, the detection matrix, install/uninstall/status against fake binaries, and `systemd-analyze verify` on
generated units when the tool is installed).
