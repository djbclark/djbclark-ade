# J6 plugin trust reads (Sonnet 5.5 medium, 2026-11-06)

PLAN.md I3/J6: "a Sonnet subagent summarises each plugin's source before the operator installs it". Read-only: each repository was cloned and its entry files, manifests and every server-side file read; client code grepped for network, filesystem and subprocess use; registry data from paseo.sh/plugins. Limits: for npm-kind plugins the git commit the registry names was read, not the published tarball (integrity hashes not checked); test and pure-UI files skimmed. The operator installs in Wave 3 (operator step); nothing here was installed or run.

## Bottom line

- **Install as-is**: getpaseo/claude-code-entrypoint-env, dennyferra/baton (one setting), tomgrin10/vitals, gpambrozio/skills, omercnet/tell-agent, omercnet/pr-radar, djbclark/questions-please.
- **Install with settings or caveats**: fullstackhouse/asks, tomgrin10/session-guard (Mac setting), sm1ee/session-recovery, sm1ee/session-janitor, j0rdsta/plan-auto.
- **Only if wanted, after reading the entry**: babo-jeonguk/usage-auto-resume (reads Claude and Codex login tokens), kapybara-org/zerosub (rewrites every session's login home).
- Plugins that read Claude/Codex tokens: usage-auto-resume, zerosub. Plugins that run unattended and send prompts to agents: asks, session-guard, usage-auto-resume, zerosub, plan-auto. Only asks, usage-auto-resume, zerosub and pr-radar (through `gh`) touch the network; no plugin calls a host other than those named in its entry.
- **Two PLAN corrections**: (1) **pr-radar does not replace pr-wait's waiting half** (J6 said it would): it is a "needs you" dashboard refreshed every 2 minutes, it does not block or poll until merge-ready; the waiting half is `gh pr checks --watch --required` plus the E8 Action (D10), which already covers it. (2) **session-guard's in-place pause is Linux-only**; on the Mac with the default `includeNativeSubagents=true` it logs "Native worker protection requires Linux" and never pauses; set `includeNativeSubagents=false` to get cancel-then-continue.

## Per plugin

1. **omercnet/tell-agent 2.0.1** (npm `@omercnet/paseo-tell-agent`, MIT; github.com/omercnet/paseo-plugins/tree/HEAD/tell-agent @ 55f572c; 44 installs, updated 2026-11-02). Client-only (~700 lines): `/tell [--interrupt] <agent> :: <msg>`, a composer pill, a panel. Sends the *current* agent a prompt "tell <id>: msg" via `paseo.agents.ref(source).send(…, steer|interrupt)`; the source agent forwards. Every send is user-initiated; no hooks, no server code, no auto-approve. Network none, files none, subprocesses none, settings none, runtime deps 0. **INSTALL.**
2. **fullstackhouse/asks** (git, no version, **no licence file**; github.com/fullstackhouse/paseo-asks @ 617c145, 2026-10-20; 58 installs; 16 newer upstream commits not reviewed). Hooks: before `agent.create`, `agent.session_open`; on created, turn_ended, permission_requested, archived. **Injects an MCP server ("asks", stdio bridge) into every agent created.** Starts a 127.0.0.1 HTTP listener with a bearer token (server.json, 0600). Sends prompts on its own (a nudge when a turn ends on a question, a Refresh prompt, answer text; steer; on-disk outbox). Auto-approves narrowly: `mcp__asks__*` tool calls only. "Discuss" starts a read-only side-chat agent. Subprocess: `gh pr view <url> --json …` every 2 minutes for PR asks (your gh login; looks in /opt/homebrew/bin, /usr/local/bin, /usr/bin). Files: `$PASEO_HOME/plugin-data/asks/` only (bridge.mjs rewritten on every start). Settings none, runtime deps 0. **INSTALL WITH EYES OPEN**: the more invasive of the inbox pair; the missing licence is a gap. J6 keeps one of asks / questions-please after a week.
3. **djbclark/paseo-plugin-questions-please 0.1.3** (MIT; @ 6b4aa88, updated 2026-10-31; 5 installs; upstream main has 2 newer commits, head 106fe91, not reviewed). Client-only (~600 lines): a screen, settings screen, sidebar item, Command Center item, a capture-phase keydown listener for the shortcut (localStorage). Reads the agent list, opens the next waiting agent. Cannot send, approve or write. Network none, files none, subprocesses none, deps 0. **INSTALL.**
4. **dennyferra/baton 0.3.1** (npm `paseo-baton`, Apache-2.0, provenance-published; @ edd3e51, 2026-10-27; 16 installs). Hooks: turn_started, turn_ended, closed, archived; RPCs continue, archive, open, read, create-now, wake. After 15 min idle (default) it **spawns a handoff-writer subagent** (child of the idle agent, told to use no tools; costs tokens) writing `<workspace>/.paseo/handoffs/<agentId>.md` inside the repo (add `.paseo/` to .gitignore). "Continue" (user click) creates a fresh agent with "Read <path> and continue the task". Deletes its own handoff files (stale on regeneration; cleanup after 3 days). Subprocesses: read-only `git` (branch, status, log -n 8, fsmonitor off), `open`/`xdg-open`. Network none. Settings: idleDelayMinutes 15; conversationDetail "standard"; includeRepoState true; handoffDirectory "" (→ `<workspace>/.paseo/handoffs`); deleteStaleHandoffs true; waitForSubagents true; cleanupOldHandoffs true; cleanupAfterDays 3; handoffProfileId "" (idle agent's own model); ignoredWorkspaceIds/ignoredProjectIds/knownProjectIds empty; ignoreNewProjects false. Deps 0. **INSTALL WITH SETTINGS**: `handoffProfileId` → a cheap model; consider `ignoreNewProjects=true`; budget for the automatic writer.
5. **tomgrin10/session-guard 0.5.1** (npm `paseo-session-guard`, MIT; @ 416a6f7, 2026-10-29; 5 installs; needs Paseo ≥0.14.0). Hooks turn_started/turn_ended; RPCs status, pause, resume, dismiss; one read-only agent tool `session_guard_status`. Polls provider usage every 15 s. At 100 % session usage pauses every protected agent: SIGSTOP of Claude/Codex processes on Linux, `cancelAgent` elsewhere; after the reset sends a continuation prompt ("Your previous turn was paused…", steer) with no human step. Network: short-lived local WebSocket to the daemon (ws://127.0.0.1:6767/ws or PASEO_DAEMON_URL), auth via PASEO_PASSWORD, PASEO_PASSWORD_FILE or ~/paseo-hub/secrets/daemon-password; no external host. Reads `$PASEO_HOME/config.json`, /proc/<pid>/{stat,environ} (Linux, PASEO_AGENT_ID only); writes `plugin-data/session-guard/`. Uses a **private API** (`@getpaseo/client/internal/daemon-client`) that may break on upgrades. Settings: enabled true; protectByDefault true; thresholdPct 100; pollSeconds 15; resetGraceSeconds 30; resumeSpacingSeconds 5; autoResume true; includeNativeSubagents true; workspaceLabels true; windowIds ["five_hour","session"]. Deps 0. **INSTALL WITH SETTINGS**: on the Mac `includeNativeSubagents=false` (else `engine.ts:516` skips every pause); consider `protectByDefault=false` for the first week.
6. **babo-jeonguk/usage-auto-resume 1.3.2** (git, MIT; @ 5c749c6; 254 installs, 2026-11-03; 5 newer upstream commits incl. OpenCode support, not reviewed). Hooks: before session_open; on turn_started, turn_ended, archived, permission_requested, created, closed; RPCs list, reschedule, resume-now, note. Detects usage-limit stops, keeps one durable resume job per agent, later sends the continue prompt (~700 chars, steer) unattended; "Labs" overload retry off by default. **Reads credentials**: Claude OAuth token from the macOS Keychain item "Claude Code-credentials" via `/usr/bin/security find-generic-password -w` (Keychain prompt) or `~/.claude/.credentials.json` ($CLAUDE_CONFIG_DIR); Codex tokens from `$CODEX_HOME/auth.json`. Hosts: GET api.anthropic.com/api/oauth/profile and /api/oauth/usage (Bearer); GET chatgpt.com/backend-api/wham/usage. Does not refresh or write credentials. Subprocesses: `claude auth status --json`, `codex app-server`, `agy -p /usage`. Writes `plugin-data/…/history` (atomic). Settings: disabledProviders [] (all ON); overloadRetry false; continuePrompt null. Deps 0. **INSTALL ONLY IF YOU ACCEPT A PLUGIN HOLDING YOUR CLAUDE/CODEX TOKENS**; session-guard does the same job from Paseo's own usage reports without touching a credential. If kept: `disabledProviders` for unused providers.
7. **tomgrin10/vitals 1.0.0** (npm `paseo-vitals`, MIT; @ d81ce82, 2026-11-05; 21 installs). Handlers vitals.snapshot/pulse/agent; one read-only agent tool `vitals_host_snapshot`. UI: sidebar meters, dashboard, composer RAM/disk pill. Subprocess: `docker stats --no-stream`, `docker ps` (if docker exists). Reads /proc on Linux only. Never kills or signals. Network none; writes none. Settings: display toggles. Deps 0. Mac caveat: per-process and per-agent detail is Linux-only; the Mac gets host CPU/RAM/disk and Docker. **INSTALL.**
8. **gpambrozio/skills 0.4.0** (npm `@gpambrozio/paseo-skills`, MIT; github.com/gpambrozio/paseo-plugins/tree/HEAD/skills @ d04187e; 905 installs). Reads `~/.claude/skills`, the installed-plugins manifest under ~/.claude, repo `.claude/skills` and `.agents/skills`, `~/.codex/skills`, Hermes skills; read-only. "Invoke" sends `/skillname args` on a click. Network none, subprocesses none, writes none, settings none, deps 0. **INSTALL** (least invasive of the set).
9. **omercnet/pr-radar 3.2.1** (npm `@omercnet/paseo-pr-radar`, MIT; @ 55f572c, 2026-11-02; 66 installs; monorepo has 53 newer commits). Two RPCs and a 2-minute background refresh. Subprocess `gh` only: `gh api user --jq .login`, `gh search prs --author|--review-requested=<viewer>`, `gh api graphql -f query=…` (read-only). File `plugin-data/pr-radar/inbox-state.json` (0600, atomic). Sends nothing on its own. Deps 0. **Correction to J6**: a dashboard, not a waiter; it does not replace pr-wait's waiting half. **INSTALL as a viewing aid.**
10. **sm1ee/session-janitor 0.1.6** (git, MIT; @ e901fef, 2026-10-26; 60 installs). Build step `npm ci --ignore-scripts --omit=dev`; **8 runtime packages** (@getpaseo/client 0.12.0, protocol, relay, ws, zod, semver, tweetnacl, base64-js), lockfile-pinned. Background worker every 5 min: archives finished subagents after 6 h quiet, **permanently deletes archived sessions** (records and conversation history, not files) after 3 days via a private daemon-client `deleteAgent`; manual "Delete this session…" needs typed DELETE. **Starts in PREVIEW with automation off** (`enabled` false). Reads `$PASEO_HOME/paseo.pid` and the daemon's `local-credential` (loopback or unix socket, daemon identity checked), lists `~/Library/LaunchAgents` names, reads session-recovery's holds file; writes `plugin-data/paseo-session-janitor/`. Subprocess `ps -p <pid> -o ppid=`. Pinned to the 0.12.0 client adapter, CI covers Paseo 0.11.4–0.13.0: **confirm against 0.15.x before enabling**. **INSTALL WITH SETTINGS**: preview for a week, archive-only first, deletion last or manual-only; keep session-recovery beside it (they protect each other's sessions).
11. **j0rdsta/plan-auto** (git, version 0.0.0, MIT; @ b00f7ea, 2026-10-20; 8 installs; 268 lines). Hooks permission_requested (records Claude plan requests) and permission_resolved: when a plan is approved with "Implement" it runs `paseo agent mode <id> auto`, sends "Continue with the approved plan.", writes an Undo row (Undo → acceptEdits). "Implement with bypass" and rejections untouched. Subprocess `$PASEO_CLI agent mode …` (argv, no shell). Network none, files none, settings none, deps 0. Trust note: moves the agent from Accept Edits to Auto after a plan approval; README calls it a workaround on Paseo internals (getpaseo/paseo#3001). **INSTALL ONLY IF AUTO MODE AFTER A PLAN IS WANTED.**
12. **kapybara-org/zerosub 1.5.1** (npm `@kapybara/zerosub`, MIT; @ 901a780; 561 installs, 2026-11-06). Hooks before session_open; turn_started, turn_ended, archived; ~14 RPCs (login, remove, set default, redeem reset, fork agent…). **Sets CLAUDE_CONFIG_DIR / CODEX_HOME for every session Paseo opens** to per-account homes under `$PASEO_HOME/zerosub/homes/` (symlinked back to `~/.claude`, `~/.codex`; "nothing changes until a second account", unverified). Hosts: api.anthropic.com (GET /api/oauth/usage; POST /api/organizations/<org>/reset_rate_limits after confirm or `autoRedeem`). Sends a failover continue prompt and a handoff prompt to a continuation agent on its own. Defaults: autoSwitch true; autoContinue true; moveAgentsOnDefaultChange true; showComposerPill true; balanceNewAgents false; autoRedeem false; useCredits false; forkOtherProvider false. ~5k source lines. **DO NOT INSTALL unless several Claude/ChatGPT subscriptions are in use** (as J6 says); then read `server/claude.ts` and `server/homes.ts` first.
