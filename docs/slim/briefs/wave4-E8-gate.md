## 1. `bin/review-launch` (new, ~300 lines plus tests; permanent, survives the Wave 6 shim removal)

1a. **Interface**: `review-launch --mode review|read-only -C WORKTREE --schema FILE (-p TEXT | -f FILE) [--model M] [--max-turns N] [--timeout S] [--json]`. It runs ONE `claude -p` and prints the run's `structured_output` JSON on stdout (nothing else on stdout). Exit codes: 0 output produced and the boundary held; 2 usage or a refused launch (bypass requested, a non-existent worktree, a schema that does not parse); **77 tripwire** (a tool call outside the allowlist, a read refused outside the worktree that the mode did not expect, an MCP server present, a hook present, `permissionMode` not the expected one, an init event missing: the run is killed and its descendants with it); 3 the run ended without structured output (`is_error`, a timeout, no `result` event); 124 the `--timeout` hit. The modes: **review** = tools `Read,Grep,Glob` (init tool list exactly `{Glob, Grep, Read, StructuredOutput}`); **read-only** = `Read,Grep,Glob,WebFetch,WebSearch` (E6's six-tool mode minus `LS`, which is not a 2.1.319 tool; init list exactly those plus `StructuredOutput`). Both: `--permission-mode default` (never bypass; refuse exit 2 if `--permission-mode`/`--dangerously-skip-permissions` appear in the launcher's own argv passthrough, if `CLAUDE_PERMISSION_MODE`-style env is set, or if the init event reports anything but `default`), `--setting-sources ""`, `--strict-mcp-config` with no `--mcp-config`, `--no-session-persistence`, `--output-format stream-json --verbose`, `--json-schema <schema>`, **no `--add-dir`**, `--settings` inline JSON `{"disableAllHooks":true,"hooks":{},"permissions":{"blockReadsOutsideWorkingDirectories":true,"disableBypassPermissionsMode":"disable","deny":[the secret-path rules: ~/.config/gh/**, ~/.ssh/**, ~/.claude.json, ~/.claude/projects/**, ~/.aws/**, ~/.netrc, ~/.config/sudo-secretspec/** and the like]}}`, cwd = the worktree. The environment is scrubbed as `local-review` does (`SECRET_ENV_RE` at `:98`: no token/secret/password/`GH_*`/`GITHUB_*`; keep `HOME`, `PATH`, `CLAUDE_CONFIG_DIR` if set, the OAuth path needs `HOME`). The prompt is passed as argv (`-p`) or read from `-f` by the launcher and passed as argv; the launcher never writes it into the worktree.

1b. **The boundary is proven from the run's own output**: parse the stream; find the init event by `type == "system" and subtype == "init"` wherever it falls (it is not the first line); assert `tools` equals the mode's set exactly, `mcp_servers == []`, `permissionMode == "default"`, `cwd` is the worktree; never assert that `skills`, `slash_commands`, `agents` or `plugins` are empty (built-ins appear). Every `assistant` event's `tool_use` name is checked against the allowlist (tripwire 77 on the first miss); `Read`/`Grep`/`Glob` inputs with a path outside the worktree trip too (belt and braces: the key already refuses them, and the refusal appears in `result.permission_denials[]`, which is read and logged). `result.structured_output` is the output; `result.is_error` is exit 3.

1c. **Boundary self-check** (`review-launch --check`, and run automatically before a launch, cached): with the same settings and arguments, launch a canned prompt that asks the model to read (i) a temp file the check created outside the worktree, (ii) `~/.config/gh/hosts.yml`, (iii) `~/.ssh/`, (iv) `~/.claude.json`, (v) `~/.claude/projects/`, (vi) `~/.claude/CLAUDE.md`, and to report each read's outcome in the schema; the check passes only when every read is refused, except (vi), whose exposure the slice **records as accepted** in the report if it is readable (the documented "files Claude Code itself needs" exemption; test `--bare` as an alternative and report which the launcher uses). The result is cached under `~/.local/state/review-launch/check-<sha256 of claude --version + the settings JSON + the fixed argv>.json`; a changed version or launcher re-runs it; a failed or missing check refuses every launch (exit 2 with the reason). The suite runs the same check against a **fake `claude`** on PATH (a Python script that emits a canned stream) in both the passing and the failing shapes; the live check is an operator step (report G) because CI has no Claude login.

1d. **The isolation checks ported from `local-review` as tests** (`tests/test_review_launch.py`): clean detached worktree at the exact head with the base pinned by SHA (the caller's job in E8's `review-pr` wrapper below; the launcher refuses a worktree whose `git status --porcelain` is non-empty or whose `HEAD` is not the requested SHA when `--head SHA` is given); scrubbed env; the init assertions; the untrusted-author refusal (exit 2 unless `--allow-untrusted`, in the wrapper, not the launcher); descendant kill at the end or at timeout (`os.killpg` on the launcher's own process group, macOS and Linux).

1e. **`bin/review-pr PR [--allow-untrusted] [--model M] [--json]`** (new, small): the thing the lead runs for rule 11. It creates the clean detached worktree at the PR head (`gh pr view --json headRefOid,baseRefOid,author`), refuses an untrusted author, runs `review-launch --mode review` with the review schema `config/review-schema.json` (`{"verdict":"APPROVE"|"BLOCK","head":"<40-hex>","findings":[{"file","line","severity","summary"}],"note"}`) and a prompt that gives the diff command to run inside the worktree (the model runs no commands: the wrapper writes `git diff BASE..HEAD` into a file inside the worktree before the launch, and the prompt names it), prints the marker line ready to paste (`<!-- adversary-verdict:v1 {...} -->` with the full head), writes `~/.local/state/review-launch/<owner>__<name>-pr<N>-<head>.json`, and removes the worktree. It never posts to GitHub.
