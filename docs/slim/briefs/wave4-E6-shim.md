## 1. The shim (`bin/acp-dispatch`, rewritten to ~600 lines)

1a. **Surface kept**: `acp-dispatch <agent> --model M --kind KIND --name NAME (-p PROMPT | -f BRIEF) [-C DIR] [--role] [--frontier-reason] [--effort] [--task|--out] [--perm all|read-only|deny] [--timeout S] [--lead NAME] [--detach [--no-wait] [--wait-timeout S]] [--dry-run] [--json] [--min-headroom] [--est-pct] [--load-wait S | --no-load-gate]`; subcommands `footer`, `check`, `outcome`, `wait`, `tell`. **Dropped**: `resume`, `reroute`, `auto-resume`, `extend`, `finalize`, `reap` (and `--install/--uninstall`), `cursor-cloud` (E9 kept `bin/cursor-cloud`; the dispatch path to it goes: say so), `--checkpoint`, `--no-preflight`, `--no-auto-resume`, the launchd runner scripts and the reap plist (`launchd/*acp-dispatch*`), the sudoers line (operator batch). Exit-code contract kept: 0 DONE, 1 unfinished/non-zero, 2 usage/refused, 3 no report, 4 BLOCKED, 75 too hot, 77 tripwire, 124 timed out.

1b. **Agent name → Paseo provider** (E6 requirement): claude→claude, codex→codex, antigravity→antigravity, cursor→cursor (cursor-agent), opencode→opencode, hermes→hermes, omp→omp (grok is retired, 2026-11-07 ruling: not in the map); any other name exits 2 with the list. `--model M` → `--provider P/M` (research item 10). **`--mode` is always passed** (Claude's default is `auto`): `--perm all` → the provider's default editing mode as `paseo provider ls --json` reports it (`defaultMode`), `--perm read-only` → for **claude**: not `paseo run` at all but `bin/review-launch --mode read-only` (the boundary; the shim's record says `boundary: review-launch`); for every other provider: a non-editing mode id verified at launch by `paseo agent mode <id> --list` after creation (the agent is created with `--mode <candidate>`, the listed modes are read, and the run is **stopped and the launch refused (exit 2)** if the candidate is not listed or is not the active mode; candidates: codex `read-only`, else refuse), documented as "provider-mode strength, weaker than review-launch"; `--perm deny` → claude: `review-launch --mode review` (no network); others: refused (exit 2) unless the provider lists a no-tool mode (none known). A `frontier` kind keeps **`agent_guard.py`'s identity policy, the estimate floor, the in-flight reservation and the per-wave cap** (`frontier_judged`, `inflight_cap`, `reserved_usage`, `estimate_floor_and_cap` and what they need) in front of `paseo run`: port them, do not drop them; `tests/test_acp_dispatch_frontier_reason.py` and `test_acp_dispatch_gate.py` seed the shim's frontier test.

1c. **Launch**: `load-watch admit --wait S --json [--max-agents N]` first (exit 75 when too hot, unchanged; `bin/load-watch:1631-1878`); then `paseo run --provider P/M --mode MODE --no-wait --json --title NAME --cwd DIR --label ade.kind=KIND --label ade.name=NAME --label ade.lead=LEAD "<prompt>"` where the prompt is **argv**: one paragraph that names the brief file (`-f BRIEF`, copied to the report's out dir, never into the repo), the report path, and the footer (`footer_text`), never `--prompt-file` (none on `run`) and never `--output-schema` (not with `--no-wait`). The record (`~/.local/state/bigteam/<task>/jobs/<name>.json`, atomic, `.get` reads) stores `paseo_agent_id`, `provider`, `mode`, `boundary`, `started`, `wait_timeout`. **Live-agent count**: `count_agents()` reads `paseo ls -g --json` (not `-a`: archived agents are not live; E5's finding) filtered to `status in {running, idle? no: running only}` plus the label `ade.lead` (use `paseo ls --label ade.lead=LEAD --json` if the filter works on 0.15.3, else filter client-side) and releases the `--max-agents` reservation only once the new agent is countable (poll up to 10 s); the handoff test: a burst of 20 shim launches against a fake `paseo` and a fake `load-watch` still hits the 14-agent cap (`tests/test_acp_dispatch_load_gate.py` seeds it).
