## 1. The shim: `skills/session-finder/relay.py` rewritten (~100 lines, stdlib only)

1a. Resolve the target: a Paseo agent id or `shortId` prefix, an agent `name` (title), or the literal `self` (→ `$PASEO_AGENT_ID`); resolution reads `paseo ls -a -g --json` (fields: `id, shortId, name, provider, status, cwd, created, background`; research item 2). Anything that does not resolve to exactly one Paseo agent is refused with exit 3 and a message naming the retirement: "relay.py reaches Paseo agents only since 2026-11-06 (herdr and Orca panes retired 2026-10-31); target X is not a Paseo agent". No pane, tmux, herdr, Orca or Pi route survives.

1b. Send: `paseo send ID --no-wait --json` with the text from the positional argument or `--message-file PATH` (`-` reads stdin). Parse the JSON `status`: `sent` or `completed` → print `delivered` and exit 0; `queued` → print `queued (accepted by the daemon, not yet delivered: the target has not been quiet for 2 s)` and exit 2; `timeout`, `permission`, `error` → print the status and exit 2; a non-zero exit from `paseo` or unparseable JSON → print the stderr and exit 1. **Never read `$?` from `paseo send` as delivery** (research item 1: every status exits 0).

1c. `--wait S`: after the send, `paseo wait ID --timeout S --json`; `idle` → exit 0, `timeout` → print `wait timed out after S s` exit 2, `permission` → print it exit 2. `--ack NAME`: appends "Reply with `ack NAME` through relay.py" to the message text, nothing more (there is no native ack; standing order 10's "first message asks for an ack" is kept as text); the sender verifies the ack by reading its own inbox, as today.

1d. Keep `--help` honest: list only the flags that exist (`TARGET`, `MESSAGE`, `--message-file`, `--ack`, `--wait`, `--via` refused with the retirement message, `--pending`/`--sweep`/`--retire`/`--transfer-expectations`/`--expect-ack` refused with "retired 2026-11-06: Paseo has no outbox; see `paseo permit ls` for pending permissions").

1e. Removal line: a dated comment at the top, "Shim, removed in the follow-up PR after one live cycle (PLAN.md F, Wave 6; at the latest 2026-11-20)", and one test that fails after 2026-11-20 (`datetime.date.today() <= date(2026,11,20)`), as PLAN.md I1 asks.
