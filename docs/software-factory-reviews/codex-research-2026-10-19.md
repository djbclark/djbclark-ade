
# Software factory within ADE everywhere — independent Codex research

Research date: 2026-10-19. Repository read-only; report and evidence files only in the assigned report directory. Recommendations below are proposals, not operator decisions. The proposal is v2.3, decided; software-factory §12 overrides its earlier sections. Local documents are unindexed by graft; full requested documents were read directly after graph lookup returned unrelated code.

## 1. Verdict

Add the factory as an optional ADE workflow, not another agent platform. Put its small deterministic state machine in `tools/factory`, dispatch exclusively through `acp-dispatch`, and expose job decisions through the planned Paseo Helm panel and existing Hermes notifications. Start contracts and preservation in Phases 0–1; prove one local-owner job after Phase 2; use it as an additional Phase 4 pilot gate before claiming unattended or portable operation. Preserve Orca until its DAG replay gate passes. Keep human merge in v1, but explicitly resolve the older document's contrary auto-merge ambition. Current rules require an adversary verdict before PR creation; that is necessary but is not human merge authorization. The hardest missing work is durable reconciliation across dispatch, CI, workspace and human decisions—not the dashboard. Cow pastures remain the Mac adapter; Paseo worktrees are the decided portable default. Neither contains arbitrary code.

## 3. Corrections

3.1. **Execution is already a service, not a new subprocess loop.** Claim: the design invokes `acp-run` directly (design:101–115). Artifact: `~/CLAUDE.md:101–111` requires dispatch; `bin/acp-dispatch:54–60` specifies “jobs/<name>.json”; its header already documents role/kind, detach, rearm, reap, model read-back and delivery checking (4–45,63–101,174–200). Consequence: factory owns workflow transitions; dispatch owns agent attempts. A factory journal references dispatch task/job IDs and must not rewrite their records. Reconcile a recorded launch intent before retrying an uncertain launch.

3.2. **A state machine does not replace the macro DAG by implication.** Claim: adding the factory orchestrator covers existing orchestration. Artifact: proposal:594 says “The DAG is Orca's”; replacement requires the Phase 4 replay gate. `docs/orca-integration.md:19–47,91–96` documents dependency/worker completion and acknowledgement behavior. Consequence: factory owns one job's bounded lifecycle and uses the shared launch interface; leave cross-job dependency scheduling with Orca until parity is demonstrated. Do not make two schedulers authoritative for the same transition.

3.3. **Read-only support is specific and narrower than generic ACP.** Claim: arbitrary adapters can be made safe by telling them not to edit, copying a checkout and rejecting a diff (design:141–153). Artifact: `tools/acp-run/README.md:28–54` documents native read-only implementations for **claude, codex, opencode and zcode**; the documented rule is “Every other agent is refused with exit 2” (45–46). Claude allows selected reading tools and removes Bash/MCP/user settings; Codex uses its native read-only sandbox, including read-only shell access; OpenCode uses permission rules; zcode uses plan mode/tool denials. Consequence: use only a capability-proven adapter for reviewers. A post-run tree hash detects some damage after the fact; it does not prevent filesystem, credential or network effects. This is especially material here: `docs/queue.md:6–16` records a prior Codex read-only run failing and the temporary `--perm all` plus tree-check workaround. That supervised advisor workaround is not an unattended-factory security gate. Reviewer artifacts should be captured from the response by the controller into run-owned files; a strict read-only reviewer cannot be required to write `verdict.json` itself. Reuse dispatch's existing stdout recovery (`bin/acp-dispatch:83–93`, `report_source: final-message`) and adapt the reviewer brief/delivery contract explicitly; retain its refusal/fake-tool-call/nonzero-exit checks rather than inventing a second success detector.

3.4. **Resume is conditional, and `--verify` does not make a successful exit a passing test.** Claim: resume means only `session/load`, and successful process delivery proves verification (design:153,161–208). Artifact: `tools/acp-run/README.md:582–595` prefers advertised `session/resume`, falls back to supported load, and fails on unsupported/unknown sessions; 490–498 describes dispatch keeping the original session ID. There is no verified universal per-agent resume matrix in these files. Most importantly, 274–283 says final verification failure “preserves exit 0” (and records `verify=pass|fail`). Live `acp-run --help` confirms the flags, not each adapter's actual capability. Consequence: record advertised capabilities and applied permissions/model before admission; collect an explicit controller-owned verification result. No `DONE`, process exit 0, model assertion, or successful `--verify` invocation substitutes for actual required CI checks on the exact reviewed SHA. Do not use `--verify` to start heavy local tests contrary to CI-first.

3.5. **Native macOS does not have bubblewrap here.** Claim: agy proposes bwrap isolation as an immediate implementation (agy-full-and-worktree:22–29; design:631,689–690). Artifact: the read-only platform probe returned `"bwrap": null`; it found `/usr/bin/sandbox-exec`, `/opt/homebrew/bin/container`, `/opt/homebrew/bin/podman` and `cow`. No sandbox policy/runtime was exercised. Proposal:130–134 calls out same-user limits and a trusted vps; Q4 rejects Nix on macOS (proposal:743–746). Consequence: a Linux namespace sandbox is an option on a Linux runner, not a native Mac command. On this Mac, the installed Apple container/Podman paths are candidates for Linux VM isolation; Seatbelt/native agent sandboxing is another capability to validate. Presence alone proves none of the credential, network or mount boundaries. Use CI on its declared host, and gate arbitrary unattended builds on tested containment. A trusted vps is a trust designation, not isolation from a malicious job.

3.6. **Scrubbed environments and Git guards are incomplete boundaries.** Claim: removing push credentials from an environment plus refusing main/master makes early unattended work safe (design:767–773,807–809; agy-full-and-worktree:13). Artifact: `tools/acp-run/README.md:143–176` calls config stripping “a startup-reliability switch, not a permission control” and says it is “not secret-free.” `bin/cow-pasture:69–87` scrubs ignored secret-looking files but only warns about tracked secrets; its dependency exemptions are 54–58. `skills/cow-workspaces/SKILL.md:71–82` also documents trust/preseed behavior. Consequence: same-user jobs may still reach CLI credential stores, SSH agents, Keychain or other files unless the execution boundary excludes them. Keep forge write credentials in the controller; reviewer sessions receive no write credentials. A worktree check and protected-path policy are defense layers, not a replacement for an OS boundary or forge rules. Use the actual default branch, not just the literal names main/master. Treat checked-in setup hooks and test code as execution too.

3.7. **Pastures and worktrees are already an explicit, platform-dependent decision.** Claim: universal `git worktree` and rejecting clone-based workspaces (design:588–635). Artifact: proposal:605 says “Paseo worktrees are the portable default,” retaining cow for Mac speed/non-git work. `skills/cow-workspaces/SKILL.md:14–19,23–45,89–97` documents APFS copies with independent `.git`, scrubbed ignored secrets, and linked-worktree/bare refusal. Its 49–58 describes `--orca`; the older `docs/orca-integration.md:122–155` claim that cow cannot compose with Orca is stale. Consequence: do not re-ask the operator to pick one universal topology. Use a workspace-provider contract, preserve source/branch identity, and make cleanup provider-specific. A locked builder workspace can serve immutable review snapshots in parallel; an exclusive lock for every reader unnecessarily serializes them.

3.8. **The front end is already chosen, and the two notification tools have different recipients.** Claim: a separate static dashboard and a new Telegram bot are required (design:99–115,347–394,508–519). Artifact: proposal:597,602–607,625–641 gives Helm, fleet status and quota panels to the ADE Paseo plugin and says “Keep both; Hermes is the always-on assistant, Paseo the workbench.” `~/.local/bin/hermes-ping:1–21,109–110` is the existing phone-delivery command. `skills/tell-chief-of-staff/SKILL.md:8–29` targets the Grok Bot chief-of-staff webhook, not the Hermes phone inbox. Consequence: build a small factory view-model for Paseo and a CLI status command first; reuse `hermes-ping` for requested notifications. Localhost polling alone does not reach a phone. Authenticated actions, CSRF protection and revision binding remain necessary regardless of which UI hosts them.

3.9. **Hardcoded role examples violate decided routing.** Claim: Opus for every spec and approver, agy Gemini for UX, cline code fallback (design:229–260). Artifact: proposal:891–900 disables Copilot, Gemini CLI and Qwen, restricts cline to Hermes/techno-euphora, requires an explicit yes per omp run, and describes Codex's $100 plan; 925–952 labels frontier “advise only” and assigns code work to cheaper eligible tiers/Sonnet/GLM as appropriate. `config/routing.toml:192–220` admits agy Gemini for bulk/research/mechanical, not code. Consequence: classify the work first. Use research/mechanical for extraction and routine edits; use judgment only for actual architecture/security decisions. The mandatory adversary remains Claude Opus per proposal:928 and `~/.claude/agents/adversary.md:1–26`; an eligible cheap second code reviewer must also support enforceable read-only. Frontier never builds or edits. A provider's presence in `route_agent.py policy` is not permission to bypass its gate. The router's Codex reservation note still references the old Plus plan (`config/routing.toml:107–116,156–178`): recalibrate from current usage before treating that number as a factory budget.

3.10. **Automatic resume cannot escape workflow admission.** Claim: factory caps checked only at state transitions, while generic dispatch may later rearm a job (design:508–519,559–577; updated:807–809). Artifact: `bin/acp-dispatch:103–124` auto-resumes quota stops, uses the original session when supported and supports `--no-auto-resume`; 126–162 documents retry/reset limits; 184 says “A resume is never refused by that reservation.” Consequence: every resume, verification follow-up, canary and wrap-up must consume a reservation and obey cancellation and ownership epoch. Until dispatch can call a factory admission hook, use its existing no-auto-resume switch for factory-owned jobs and schedule through its resume API under the factory lock. Do not implement a second runner or silently change agent/model. Transfer must also quiesce reapers and scheduled resumes (proposal:492–513).

3.11. **The CI inventory has changed, but an active workflow entry is not a default-branch Linux gate.** Claim: ADE has “no CI” and private-repo limitations prevent rules (coding-factory:25–38,124–148). Artifact: read-only GitHub probes at 20:29 UTC on 2026-10-19 returned public visibility, two active workflow entries, an empty ruleset list, “Branch not protected” (404) for master, and `allow_auto_merge: false`. **Correction to the initial registry-only observation:** reading the actual files at 20:42 found default-branch `test.yml:3–14` runs on master pushes/PRs/manual invocation on `macos-latest`; `linux-ci.yml` is absent there. Linux CI does exist on `ci/run/**` overlays: the latest observed successful run is [39186083335](https://github.com/djbclark/djbclark-ade/actions/runs/39186083335), created 2026-10-19 01:35:52 UTC at SHA `c33cc142506ebadb09e4a67d4f76ae00a1205b40`. Its actual workflow says “Overlay-only on ci/base” and uses `ubuntu-latest`, stubs launchd and sets `ACP_DISPATCH_NO_GATE=1` (`remote-linux-ci.yml:3–24,42–43`). Consequence: reuse the established Linux overlay/wrapper path; do not invent another remote test farm or claim the proposal's default-branch/newcomer Linux gate has landed. This is observed hosted CI success at one overlay SHA, not testing performed by this research or proof of production Linux dispatch/permission gates. Add exact source-SHA binding and required-check enforcement. Workflow existence does not establish adversary enforcement or protected merge. `bin/load-watch:1–49` and `~/ops/site-private/bin/bg:1–33,106–118` govern local eligibility/load, not CI acceptance.

3.12. **An adversary verdict is not human merge authority.** Claim: the existing PR rule answers who merges. Artifact: `~/CLAUDE.md:114–116` requires an adversary verdict “before opening a pull request”; `~/.claude/agents/adversary.md:19–26` uses APPROVE/BLOCK and must disclose incomplete review. It says nothing about a human approving every merge. Design:80–81 chooses human merge, while coding-factory:157–178 explicitly wanted zero human clicks. Consequence: resolve that product-policy conflict once (SF-Q1), retain the mandatory adversary, map APPROVE/BLOCK into factory PASS/CHANGES without weakening incompleteness, and invalidate both review and authorization when the head SHA changes. A generic “approval” button cannot override a security BLOCK.

3.13. **Crash recovery requires reconciliation, not blind reset/replay.** Claim: reset to the last completed HEAD, rerun and notify again proves safety (design:795–825; claude-opus-round1:27–35,107–113). Artifact: proposal:449–471 requires validated generation manifests; 492–523 specifies ownership transfer, frozen writers and work bundles; 621–623 requires persisted attempt identity and says an uncertain create/send “is reconciled, never retried blind.” Consequence: inspect dispatch state and PID/start identity before launching, fence stale owners, preserve dirty work before any destructive reset, and bind rounds to spec hash, base SHA, candidate SHA and review schema. Journal write/flush/rename durability and torn records need tests beyond kill -9. An outbox enables retry, but exactly-once Telegram delivery is not promised by these artifacts; record dedup keys and accept a possible duplicate or reconcile where the destination supports it. For pushes/PR creation, query the remote identity before repeating an uncertain side effect. Do not claim a one-test proof covers power loss or all external systems.

3.14. **Review agreement is not evidence of an implemented gate.** Claim: malformed verdicts count as CHANGES (claude-opus-round1:57), or reviewers can overwrite the sole-writer job state (agy-full-and-worktree:36–37). Artifact: design:19 and §12:728–737 require a deterministic sole writer; §12 says “Reviewer infra failure (timeout, quota) must not count as CHANGES.” Consequence: malformed/missing/incomplete reviews are BROKEN/retryable infrastructure failures, consume actual run budget, and never advance approval or consume a substantive rework round. Cursor correctly rejects an exact-looking money line when usage is missing (cursor-grok-dashboard:15). A labeled planning forecast is still legitimate; it must never be displayed as measured spend or an enforceable USD cap. The agy dashboard and full responses disagree about retaining Kanban (agy-dashboard:18 versus agy-full-and-worktree:74); adopted §12 cuts it. Treat all eight files as advice, not eight independent implementations or votes.

3.15. **Do not revive a retired LLM verdict parser or deploy path.** Integration assumption to reject, not an assertion made by the design: a new LLM completion judge or post-merge deployment belongs in this workflow. Artifact: `docs/jev.md:92–101` labels that path “dispatch-verdict (retired 2026-10-11)” and replaces it with deterministic classification; design:89 excludes deploy. `~/CLAUDE.md:89–93` requires the NixOS deploy path from pushed commits and heavy Nix builds on Forgejo. Consequence: use schemas and deterministic event transitions; leave deployment outside v1 and preserve its existing pushed-head/NixOS policy if added later.

3.16. **Mac detachment is not yet proof of portable unattended execution.** Integration assumption to verify: reusing dispatch means its full background lifecycle works on every proposed host. Artifact: `skills/bigteam/SKILL.md:767–775` calls `launchctl submit` “The verified detached form”; `bin/acp-dispatch:186–200` describes launchd-specific recovery. The observed Linux workflow explicitly stubs launchd (`remote-linux-ci.yml:6,18`). Consequence: retain existing execution rather than clone it, but gate Linux unattended operation on real host lifecycle evidence or the Phase 4 Paseo adapter. A portable workspace and passing Linux unit tests do not prove reboot survival, scheduled resume or cleanup on Linux. This is an integration dependency, not a request to replace the dispatcher.

3.17. **Model preflight is not uniformly fail-closed today.** Integration assumption to verify: the shared launcher's model validation is sufficient for strict factory capability admission. Artifact: `bin/acp-dispatch:63–74` says, “If the probe itself fails the dispatch goes ahead with a warning.” `tools/acp-run/README.md:187–203` distinguishes requested/applied values and unverified read-back. Consequence: factory admission must refuse an unverified required model/permission/capability, then use the normal dispatch path. Neither a cached catalog nor `--info` creating a fresh session proves a later resume supports the same controls. Record what was actually applied for every attempt.

8.2. **Nominal job-call estimate from the adopted topology.** Let R be substantive review rounds, from 1 to 3, with one builder and two reviewers per round and one spec turn.
