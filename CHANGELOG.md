# Changelog

All notable changes to this repository are recorded here, newest first, in the
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) form. Every pull request adds its line
under **Unreleased** (AGENTS.md, code review rule 10, since 2026-10-20); a tag moves that section
under a dated heading. `ade update` (proposal 4.4 item 9) prints the entries between the commit a
machine last applied and the head it is moving to, so this file is what tells an operator or an
agent what changed and what is new. Entries end with the pull request number.

### Security

- `relay.py`: any Paseo agent could close another peer's `--expect-ack` or first-contact link on a transcript-less Paseo sender (a forged ack), because `--sweep` took the peer's identity from rendered `paseo logs` text: a `[relay from … PEER]` header, a `[Message received] PEER` line inside a multi-line message body, or an exported `PASEO_AGENT_ID` all passed for the peer. The Paseo timeline is now a delivery witness only and never closes an ack (`timeline_ack`, `timeline_base` and the records' `tl_base` are gone). Such a sender's expectation and first-contact link close only when the target answers through relay.py, identified by the fleet and delivered or kept by the route (`ack ID` closes the expectation, `ack <sender id>` closes the first-contact link, which also fixes those links staying one-way for a non-Paseo peer, including an answer that arrives before the asker's own run has written the link), including an answer relay queued for a busy Paseo recipient, resolved at delivery from the caller recorded when it was queued. A same-user process can still forge the fleet's identity (an exported `PASEO_AGENT_ID` on a lone `self` row, `docs/queue.md` item 9(b); an exported `CLAUDE_CODE_SESSION_ID` naming a peer's session, for a caller whose own Claude has no registry entry, adversary PR 173 C2); a direct send from an agent nested under a Paseo agent still goes out under the parent's title (`docs/queue.md` item 9(d)). Also fixed: a transcript-holding outer session no longer outranks the nested session that actually runs relay as the sender (the reply, its footer and the `--retire` self-check named the parent), and a queued send from a nested agent no longer takes its parent's inherited `PASEO_AGENT_ID` as sender, failure-notice destination and Paseo attribution (#173).
- `firecrawl-router`: the serve-only form refuses a non-loopback `--listen` like `--open` does,
  and the address actually bound is checked before the first request is served (#14).
- `cursor-cloud` and `firecrawl-router`: endpoint variables must be https or loopback, bearer
  keys never follow a redirect or a client-chosen request target, and `cursor-cloud` runs under
  `python3 -I` with proxy, CA and `PYTHON*` variables scrubbed from the key-holding process (#15).
