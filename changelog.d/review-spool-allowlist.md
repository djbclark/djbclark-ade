### Fixed

- `bin/review-launch`: a review may read a regular `toolu_*.txt` in its own session's oversized-output spool, which lives outside the worktree, instead of being killed for it. Only that exact file is exempt, and the spool is looked up under `$CLAUDE_CONFIG_DIR` when set (else `~/.claude`). A Read of a symlink that lies outside the worktree trips even when it resolves inside, because `realpath` follows it; a link inside the worktree (`CLAUDE.md -> AGENTS.md`) is still read normally and judged by where it resolves. This stops a frontier review losing paid work for touching the harness's own spool (operator ruling 2026-11-20). docs/review-boundary.md describes the exception, and the long-path project folder name is tested against an independent JS encoder.
