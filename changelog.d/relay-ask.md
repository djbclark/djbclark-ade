### Added
- `relay.py --ask`, `--inbox`, `--answer` and `--withdraw`, a question ledger for leads: a decision for a lead is a 0600 record under `~/.local/state/relay/asks/` that the lead reads with `--inbox`, never text typed into its turn, so a lead on a card or mid-turn no longer queues (cap 20) and loses its replies. `--ask` opens the asker's expectation under the question's id and queues one wake-up text per target outside every cap; the pick comes back as `ack q-ID pick N: <option>` and, authoritatively and independent of the deferral queue, through `--inbox --mine` (the asker's own answered questions it has not seen, marked `answer.seen_by_asker`). Only the addressed lead, or the operator with the question's nonce and the operator token file (`--nonce`, `--operator-token-file`, `--via-label`), answers; a caller with no session reads no `--inbox` without the token file. `--pending` lists questions and `--sweep` expires and prunes them (#261)

### Changed
- `relay.py --cancel` refuses (exit 2) a queued message addressed to the caller: a message is read when it is delivered, and only its sender or the operator from a shell cancels it (#261)

### Security
- The question ledger proves who is asking, answering or withdrawing: a process that only exports another session's `PASEO_AGENT_ID` or `CLAUDE_CODE_SESSION_ID` is refused (exit 2) by `--ask`, `--inbox`, `--inbox --mine`, `--answer` and `--withdraw` (a Paseo agent must host the process, a Claude session must be in the registry); records, the operator token and `--ask --message-file` are read only when regular files of the user (no symlink, no FIFO), a loose operator token is replaced, the ledger directory is 0700 and never a symlink, and `--cancel` refuses when it cannot tell who is asking (#261)
