### Fixed

- `ade-worker-run`: one WORKERS window per lead and repo. The typo guard ("no WORKERS window is named for work ..., not a second window") counts only the lead's windows of the launch's own repo (the name's repo, else a legacy window's cwd repo; an unreadable repo still counts; `repo` None keeps every window), so a launch for a repo the lead has no window for opens one instead of being refused into another repo's window. A window the launch opens is created in the repo's primary checkout (`ade_ws_names.primary_checkout_of`: a submodule resolves through its superproject, a repo whose git dir is not a `.git` through `git worktree list`; a bare or separate-git-dir repo has none recorded, so the window opens in `--cwd` with a stderr warning), not in the claimed worktree `--cwd` names; the launch is refused (before anything is renamed) unless the brief names that worktree as a whole absolute path (never for `--placement main`, which keeps refusing a `--cwd` other than its window's), prints `cwd`/`requestedCwd`, and a repeat of the same `--cwd` into the window just minted is placed at the window's cwd instead of being refused; the post-launch `Cwd` check compares with that. The same brief check, stderr note and `cwd`/`requestedCwd` apply when no `--cwd` is given from inside a linked worktree. The typo guard compares repo names without case, also counts a window of the same checkout named with another `--repo`, and still counts a legacy window whose directory is gone; a brief path followed by `.old` or preceded by a prefix does not name the worktree. The paseo#9699 refusal for any other `--cwd` in an existing window is unchanged. (#709)
