### Added

- Added `bin/coding-bot` and the `tell-coding-bot` skill: any project's agent talks to the operator's cloud Grok Bot "Coding" like `acp-run` or `hermes send`, as a thin wrapper over `peer_mail.py` from the private frdminc/peer-link (the source of truth for the link, the mailbox, the wake and the fencing; first built as a webhook client in #233, rebuilt on peer-link in #269). `ask TEXT|-` sends, then blocks for the final reply to that one message (`wait --re ID --fetch` and `drain --re ID`, the same message set for both, so agents sharing the mailbox cannot take each other's replies); `send TEXT|-` prints the message id; `wait ID`; `status` (config, whether peer-link supports `wait --re`, peer_mail's `check`). The final reply is the one whose last line is `DONE` or `BLOCKED:` (every task is sent with one more line in the task file, "End your reply with a last line DONE, or BLOCKED: <your one question>.", since peer-link does not tell the bot how to finish); earlier replies are progress on stderr, fenced as received. Every accepted final reply is saved (0600, atomic) to `$CODING_BOT_STATE/replies/ID.md` (default `~/.local/state/coding-bot`) before it is printed, so `coding-bot wait ID` can hand it over again after an interrupted `ask`; each peer_mail wait/drain child is killed with its process group at the remaining `--timeout` + 5 s and `--interval` is clamped to the remaining budget. A reply is accepted only if every message in it is from `coding`, answers the id and has `nonce_check=ok`; otherwise exit 1 with the handover on stderr (checked before anything is claimed, so a forged message cannot make the real reply be consumed); the overall `--timeout` is enforced between replies; a zero-width character cannot hide a key from the credential check. Exit codes: 0 done, 1 failed (a send that stored nothing, a rejected reply, or a wait that failed after the send: "ID is stored; do NOT send it again" and the `wait ID` to run), 2 usage, refused text or refused `PEER_LINK_TOOL`, 4 `BLOCKED:`, 5 not picked up, 124 timeout. The `prompt`, `deliver`, `inbox` and `bootstrap` subcommands, the clipboard route, `--from`, `CODING_BOT_WEBHOOK_URL`, the `~/.local/state/coding-bot` state and exit codes 3 and 10 are gone; they never shipped in a release. Safeguards kept from the webhook client: the wrapper restarts itself isolated (`-I`) before importing anything; without `CODING_BOT_WEBHOOK_KEY` in the environment `ask`/`send` re-execute once under `sudo-secretspec run` (the task in a private file, never an argv; the hand-over believed only with a per-run random token), and there check the task (credential shapes and the vault's own `CODING_BOT_WEBHOOK_KEY`/`_URL`/`_HEADER` values: exit 2, nothing stored), keep an allowlisted environment (every other secret dropped, the key only for the send, no `PEER_LINK_TRUST`/`PEERS`/`STATE`/`CHILD_ENV`), remove proxy/`SSL_CERT_*`/CA-bundle/`SSLKEYLOGFILE`/`OPENSSL_*`/`PYTHON*` variables and run `python3 -I peer_mail.py`, which must be owned by you and not group- or world-writable; stdin is read up to 100,000 characters + 1. Needs peer-link with `wait --re`/`drain --re`. (#269)
