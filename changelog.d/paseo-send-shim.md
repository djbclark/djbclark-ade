### Added

- A `paseo` PATH shim enforces the archived-send guard in the send path itself: `libexec/agent-bin/paseo` (a bash front door; the real paseo is found past its own directory, `ADE_REAL_PASEO` overrides) hands every `send` to the new `bin/ade-paseo-guard`, which parses `paseo [global opts] [agent] send [opts] TARGET` with the hook's own parser and then execs the real paseo as asked, with the target rewritten to its successor (a completed self-handoff replaced it), or not at all (exit 4: archived with no successor, a cyclic ledger). It closes the hole of the Claude hook, which never saw a send built in a Python `subprocess.run(["paseo", "send", ...])`, a script or a heredoc'd program (a send to a replaced ex-lead went through that way on 2026-11-14); it fails open on any error of its own, never judges the message text, and is not installed by this change (put `libexec/agent-bin` first on PATH, as the ade-claim plugin's W4 hook does). New operator override `ADE_ALLOW_REPLACED_SEND=<its full id>` sends to a replaced agent that is still live (not archived, sound ledger), logged to `~/.local/state/djbclark-ade/send-guard-overrides.jsonl`; the hook accepts the same assignment before the command.
