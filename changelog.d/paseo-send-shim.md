### Added

- A `paseo` PATH shim enforces the archived-send guard in the send path itself: `libexec/agent-bin/paseo` (a POSIX sh front door; the real paseo is found past its own directory, `ADE_REAL_PASEO` overrides) hands every `send` to the new `bin/ade-paseo-guard`, which parses `paseo [global opts] [agent] send [opts] TARGET` with the hook's own parser and then execs the real paseo as asked, with the target rewritten to its successor (a completed self-handoff replaced it), or not at all (exit 4: archived with no successor, a cyclic ledger). It closes the hole of the Claude hook, which never saw a send built in a Python `subprocess.run(["paseo", "send", ...])` (a send to a replaced ex-lead went through that way on 2026-11-14); it sees only a `paseo` that PATH resolves to `libexec/agent-bin`, so on the operator's Mac a bash child (`bash -c`, a bash script, `bash <<EOF`) still reaches the real paseo because `BASH_ENV=~/.bashrc` reorders its PATH (call the shim by its path, or `env -u BASH_ENV`), it fails open on any error of its own, skips every copy of itself when it looks for the real paseo (two checkouts on one PATH do not loop), never judges the message text, and is not installed by this change (put `libexec/agent-bin` first on PATH; the ade-claim plugin's W4 hook does it only in `enforce` mode). The hook parser now reads `-o/--format` and the global options after `agent` and after `send`, and does not judge a send with an explicit `--host`/`--home` anywhere. New operator override `ADE_ALLOW_REPLACED_SEND=<its full id>` sends to a replaced agent that is still live (not archived, sound ledger), logged to `~/.local/state/djbclark-ade/send-guard-overrides.jsonl`; the hook accepts the same assignment before the command.
