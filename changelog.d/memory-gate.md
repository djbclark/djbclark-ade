### Changed

- `load-watch admit` fails toward waiting (2026-11-01; the load watcher's d8891c91 measured load 35-70 as memory starvation: ~64 MB free, ~12k compressions+decompressions/s, ~1760 pageins/s, 31+ agent processes, and the 4.0 calm boost let a slice start in every brief dip). It now refuses (exit 75) while free+speculative memory is below 600 MB (`--min-free-mb`, `LW_MIN_FREE_MB`), compressions+decompressions exceed 20000/s (`--max-mem-churn`, `LW_MAX_COMPRESSOR_S`; was 60000, sampled over 2 s) or pageins exceed 1000/s (`--max-pageins`, `LW_MAX_PAGEINS_S`). The live-`acp-run` cap (`--max-agents [N]`, bare = 14 or `LW_MAX_AGENTS`, 0 = off; one `ps`, exact argv match) gates only NEW agent starts: it is off unless the caller passes the flag, `acp-dispatch` always does and `bg` never does (a `bg` test run starts no agent, and at the cap it would starve the slices it counts). `acp-dispatch` reads `LW_MAX_AGENTS`, `LW_MIN_FREE_MB`, `LW_MAX_COMPRESSOR_S` and `LW_MAX_PAGEINS_S` from its own environment and passes them as flags (and `LW_BOOST_CALM_S` as an environment variable; every other `LW_*` is still scrubbed), and its exit-75 line and `load_gate.refused` name the gate that said no. The line and `--json` report each value plus `refused`. A `vm_stat`, `/proc` or `ps` read that FAILS where the tool exists (timeout, non-zero exit, unparsable) refuses (`memory_unreadable`, `agents_unreadable`); only an absent tool leaves its gate open, listed in `unreadable` (Linux: /proc/meminfo, /proc/vmstat). The 4.0 boost needs 10 unbroken calm minutes (`LW_BOOST_CALM_S`; `calm.json` under an flock, judged with the module defaults whatever flags the caller passed, fed by `admit` and the 20 s sampler; any hot reading resets it) and its churn line is the same 20000. `is_acp_run` also matches a framework `Python` and `-X`/`-W` options. Admissions under the cap (counted from a `ps` table that must contain the process itself, else the read fails and refuses) are reserved (`agent-reservations.json` under an flock; `admit --json` prints a `reservation` id, `load-watch release ID` and acp-dispatch release it once the agent is countable by `ps`, when it ends, or on any exit after admission (a `--detach` caller hands it to the runner instead; the countable check includes the spawned root process), `LW_RESERVE_S` 1200 s is the backstop, `--no-reserve` records none but still counts the held ones) so concurrent dispatchers cannot all pass at 13 of 14 and a runner waiting for capacity keeps its place (`load-watch renew ID`, called by the dispatch every 60 s while it waits or starts, extends it by `LW_RESERVE_S`); every real reading feeds the calm clock even for a `--boost-per-core 0` caller; `acp-dispatch` ignores a zero `LW_MAX_COMPRESSOR_S`/`LW_MAX_PAGEINS_S` (admit exits 2 on it), treats an admit exit 2 as a refusal (never start anyway), and records the validated knobs in the job record (`load_knobs`) for detached runners. Docs: `skills/loadwatch` §2a (#210).
