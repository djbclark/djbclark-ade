### Added

- `bin/changelog-fold [--check] [--repo DIR]` (2026-10-31) folds the `changelog.d/<branch>.md` fragments into `CHANGELOG.md`'s `## Unreleased` (new entries at the top of each subsection in file-name order, missing subsections created in Keep a Changelog order, an entry already anywhere in the file skipped so a rerun cannot duplicate), writes the file atomically (fsynced) and deletes the folded fragments; `--check` validates headings and the `(#N)` ending without writing; exit 0 folded, nothing to fold or valid, 1 invalid fragment (nothing written or deleted), 2 usage error, `--repo` not a directory or no `CHANGELOG.md` (`--check` included). One writer, the lead, folds through a normal PR (#190).
- `bin/ade-update` lists the entries of `changelog.d/` fragments present at its target and absent at its base (under "Unreleased (changelog.d)", once even when a fold moved them into `CHANGELOG.md` between the two revisions, and never again after the fold for a machine that already saw them as fragments; `--json` `changelog.entries`) and warns, with `changelog.stale_fragments` in `--json`, about a fragment older than 14 days on the revision it updates to; it reads fragments through the `changelog-fold` beside it (#190).

### Changed

- A pull request now adds its changelog line as a `changelog.d/<branch>.md` fragment instead of editing the shared `## Unreleased` block of `CHANGELOG.md`, so a merge no longer makes every other open PR conflict there; AGENTS.md code review rule 10 names the single folder (the lead) and the trigger, and order 9's staged list marks "CHANGELOG fragments" done (#190).
