Round 3 states plainly that the removal rule and the denylist guard against careless commands from trusted agents and are not a security boundary: a variable the command line sets, a positional or a `${X:-y}` form is unknown (held), a glob or brace at the top of a critical directory (and `~/Library`) is held, a relative `.`/`..`/glob removal is held while the directory is unknown, and a remover word the parser did not judge (`parallel rm`, `ssh h rm`, `fd -X rm`, `alias`) or a command word that is not plain holds the request. Round 4: a `cd` changes the judged directory only when `&&` (or `|| exit`) follows it, a `( ... )` group gives the outer directory and variables back, `find` from an unknown directory needs a narrowing name test, `${X:?}` and a sourced file make variables unknown, `uv run python -c`, `mv` of a critical directory and `git submodule foreach` get the same checks, the extension glob exception shrinks to `/` and the temp directories, and a variable set once to a literal, `$(mktemp ...)` or a literal `for` list is judged on its real value (#939)
