### Fixed

- `ade-claim` Paseo plugin failed to load in the daemon (`Plugin failed to load: The "path" argument must be of type string or an instance of URL. Received undefined`, `paseo plugin install` rc 1, status `failed`; #638 D2). Paseo bundles `index.server.ts` to CommonJS and `eval`s it, so `import.meta.url` is undefined there and `fileURLToPath(import.meta.url)` threw at module load (the daemon never hands a plugin its directory; `ade-yolo` works because it never asks). New `resolvePluginRoot`: a real `file:` URL still wins (plain Node ESM, the tests); otherwise the plugin root is the shared checkout `~/src/djbclark-ade/plugins/ade-claim`, from which the trusted `bin/ade_claims.py`, `bin/ade-git-guard` and `libexec/agent-bin` are still found by the parent walk (env `ADE_CLAIMS_PY` / `ADE_GIT_GUARD` / `ADE_AGENT_BIN` override). Tests cover both branches and guard against an unguarded `import.meta` use.
