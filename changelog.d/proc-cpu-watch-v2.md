### Changed

- `bin/codexbar-cpu-watch` became `bin/proc-cpu-watch --target codexbar|opencode` (2026-11-01, djbclark: "opencode serve seems to be having a CPU issue"): every subcommand takes a required `--target`; the new `opencode` target samples `opencode serve` and the commands its sessions run; one plist template (`launchd/com.djbclark.proc-cpu-watch.plist`) is installed per target as `com.djbclark.<target>-cpu-watch` with state in `~/.local/state/<target>-cpu-watch/`; every record carries its `target` and `report` shows only that target's records; an interpreter's first argument is named only when it is script-shaped (a script suffix, or a path right after argv[0]). The CodexBar job keeps its label and state directory; reinstall it after this lands with `bin/proc-cpu-watch install --target codexbar` (the old `bin/codexbar-cpu-watch` path is gone) (#226).
