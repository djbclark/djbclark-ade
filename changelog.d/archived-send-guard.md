### Fixed

- A message to an archived or replaced agent no longer resurrects it (Paseo un-archives and runs an archived agent that is sent a message; the ex-lead 994234ba came back running that way on 2026-11-14). `bin/ade_send_guard.py` decides from the completed-handoff records: a send to an agent a self-handoff replaced goes to its successor, a send to an archived agent nothing replaced is refused (`ADE_ALLOW_ARCHIVED_SEND=1` resumes one on purpose). The new Claude hook `claude/hooks/archived_send_gate.py` denies such `paseo send` / `send_agent_prompt` calls and names the successor; `completion-notice`, `fable-wait` and `deadline` use the same decision. Also hardened from the #669 review: handoff records must be owned by the reader and not group/world-writable, `home` must be an absolute path, and `ade-net-resume` no longer reads a listing without string ids as proof a lead is retired.
