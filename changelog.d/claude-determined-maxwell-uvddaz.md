### Changed
- `bin/route_agent.py` and `bin/acp-dispatch` lost the Pi capacity gate, the `agy` model-family mapping, the agy report-path and resume special cases and the
  copilot, cline and zcode provider-map entries. (#0)
- Changed `load-watch`: it attributes a spike to a Paseo agent from `paseo ls -g --background --json` by working directory (the walk up stopping at the agent's own CLI), tells it with `paseo send --no-wait --json` (reading `.status`; `queued` is not delivered), sends work that several agents share or that it cannot attribute to the operator, and drops the relay.py channel and `watcher set --relay`/`--sid` (slim-down E5) (#0).
- Changed `context-budget-check`: `install`/`uninstall` removed (exit 2); it runs as a nightly Paseo schedule (J3) (#0).
- Changed `context-watch`: it no longer imports session-finder's `fleet.py` (slim-down E5) (#0).
- Changed the quota-guard and fleet-governor successor advice and the handoff skill: a successor is launched with `env -u PASEO_AGENT_ID -u PASEO_AGENT_CWD paseo run …` and archives its predecessor by id once it has answered; the context nudge leaves compaction to auto-compaction (slim-down E4) (#0).
- Changed standing order 10's mechanics: a sourceless send (deadline, load-watch) is delivered when `paseo send --json`'s `.status` reads sent or completed; an agent's send is accepted (exit 5, queued by the daemon) and proven only by the peer's `ack <id>`; `paseo send`'s own exit status is never read as delivery (slim-down E3) (#0).
- Changed `acp-dispatch` into a shim over `paseo run --no-wait --json` and `paseo wait --json` (status field mapped to the exit codes: idle classifies the report, timeout 124, permission 4, error 3): agents are Paseo providers (claude, codex, antigravity, cursor, opencode, hermes, omp, grok; `--model M` becomes `--provider P/M`, `--mode` always passed); `--perm read-only`/`deny` run Claude through `bin/review-launch` and codex through a provider mode verified at launch, and are refused for every other provider; the `load-watch admit` gate stays, plus a Paseo-side cap on live `ade.via=acp-dispatch` agents (LW_MAX_AGENTS, default 14, exit 75); the frontier admission (agent_guard identity policy on the launch argv, estimate floor, in-flight reservation, per-wave cap) and `footer`, `check`, `outcome` stay; `tell` writes the inbox and reads `paseo send`'s status (queued is accepted, exit 5) (slim-down E6) (#0).
- Changed `skills/dialogue`: an `acp` route (now an alias of the new `paseo` kind) runs `paseo run --no-wait --json` plus `paseo wait` and reads the turn from a reply file the prompt names, instead of `acp-run` (slim-down E6) (#0).
