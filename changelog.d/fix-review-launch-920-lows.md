### Fixed

- `bin/review-launch` (follow-up to #920): while claude runs, SIGTERM, SIGHUP and SIGINT are only recorded and never raised from a handler; the main loop and the pause wait turn a recorded signal into an interrupt from ordinary code. So two signals close together end the run with exit 3 instead of `RuntimeError: release unlocked lock`, a signal at the start of the final cleanup cannot skip the `kill_all` or leave the signals ignored, and the handlers are restored even if `kill_all` fails. A signal that arrives during the final kill is no longer dropped: it is handed to the caller once claude is dead, so a stop request sent during the self-check's cleanup still stops the launch. The no-init test now asserts the reason it records. This replaces the "second signal is ignored" behaviour of #917 and #920. (#PR)
