### Added

- Gemini 4 Argon is a routable `frontier` model, fallback only (2026-10-31, operator; needs aiuse 1.5): `config/routing.toml` lists `gemini-4-argon` in `[dispatch].frontier_models` (so it runs only with `--kind frontier`) and gains the `antigravity-argon` service (`acp-run agy --model gemini-4-argon --effort high`, rank 5 in `frontier`, `pool = ["antigravity", "gemini_argon"]`, `fallback_after = ["codex", "claude"]`). It is used when astra OR Fable is short (codex below its 60% estimate floor, or the Fable sublimit below `frontier1_min_left`, where it replaces the Opus downgrade), never while both have quota: `route_agent.py plan --kinds frontier` skips it then and `acp-dispatch` refuses it (exit 2, `route-override` escapes). It fails closed: no fresh, unfrozen reading of the Argon window means the planner never picks it and a dispatch exits 5 naming the window. aiuse 1.5 files Argon as its own pool family `gemini_argon`, so `route_agent.antigravity_family` (shared by `acp-dispatch` and mirrored in `bin/failover.py`) maps `gemini-4-argon*` to it and other `gemini-*` to `gemini`; `acp-dispatch`'s reset-time and live-headroom readers and the exhaustion note use the same family. A quota refusal names the binding window (`binding window: Gemini 4 Argon weekly, N% left`), and `--dry-run` prints it on its `would refuse` line. The frontier allowance of `--frontier-reason` stays claude and codex only, and the record says so in `frontier_judged_note`. Carbon is not reachable through agy yet (Google's staged rollout, 2026-10-28). `tests/test_argon_frontier.py`. (#224)

### Changed

- Astra may run down to 20% of Codex quota left in tendcf and nix2cf only (2026-11-01, djbclark): `[dispatch.repo_overrides.tendcf]` and `.nix2cf` in `config/routing.toml` replace the 60% `codex:frontier` estimate floor and cap the estimate; `acp-dispatch` resolves the repo from `-C` through the origin remote (worktrees count) and applies it to the estimate, the in-flight reservation and the Argon fallback predicate; `route_agent.py route` and `plan` take `--repo NAME` (default: the cwd's repo). Other repos keep 60. (#224)
- The planner's frontier admission now uses `acp-dispatch`'s own arithmetic (2026-11-01, adversary R1-R3): one shared `pool_fits` with per-window estimates (`estimate_windows_from_rows`, `window_fit`), the same kind and effort filter, window-only rows and `ROOT/jobs` plus `ROOT/*/jobs` history, replacing the scalar `pool_floor`. (#224)
- `route_agent.py` reads a window `measurement_frozen` as exhausted for every provider when it reads the snapshot file (2026-11-01, adversary N7, needed for the Argon fallback): aiuse's own `--available` already did; before, only the file path trusted a frozen reading, so with a frozen Flash window the router now sees 0% where it used to see the frozen number. The planner also hands a `frontier` slice only to a pool at or above what `acp-dispatch` will demand of it (`pool_fits`: codex astra's 60% estimate floor until 3 slices are measured, then their median, shared with `estimate_pct` through `estimate_from_history`), and a fallback service (Argon) gets no burn-first bonus, so it never outranks a pool it falls back behind that is not short. (#224)
