### Fixed

- GUI-hog load-source labels: a process whose executable path the kernel will not give (exited, replaced on disk by an upgrade such as `chrome-use`, `Paseo Helper`, `node` or `uv`) is now named from libproc `proc_name`, the kernel's short name taken from the exec'd file's name, instead of all merging into one `system:?` source; `?` remains only when that gives nothing either (a zombie, a gone process, or another user's process whose path the kernel also withholds: `proc_name` answers only for the sampler's own user). Neither lookup reads argv or the environment, and there is no Linux fallback (`/proc/PID/comm` can be set by the process itself). The docs and docstring that said `?` means "the process exited" now say "unreadable (exited, replaced on disk or not permitted)", and a source-text test of `tick` that a comment could fool is replaced by behavioural tick tests.
