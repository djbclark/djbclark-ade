### Fixed

- `acp-run codex --perm read-only` never asks any more (2026-11-02): codex-acp's read-only mode is approvalPolicy `on-request`, sent with every turn, so a command the sandbox blocked (a `gh` or `curl` call, a write) became a permission request, and refusing it, the only choice, made codex abort the whole turn (`stopReason: cancelled`, no report; tendcf v5-s1 lost a 113 s review). `tools/acp-run/codex-never-ask-shim.cjs`, started as `CODEX_PATH`, forces approvalPolicy `never` while the read-only sandbox (no writes, no network) stays, so a blocked command fails and the model sees it and carries on. A turn an agent cancels after a refused permission request now fails as `FAILED escalation-abort` (exit 1), and `acp-dispatch` names it in the NO-REPORT line instead of blaming a one-hour foreground command. (#PR)
